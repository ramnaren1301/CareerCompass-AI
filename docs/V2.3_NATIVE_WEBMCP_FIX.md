# PathwayOS v2.3 native WebMCP fix

## Defects corrected

1. v2.2 called the internal fallback “connected” and reported 33 tools even when Chrome registered zero native tools.
2. The development server did not send `Origin-Agent-Cluster: ?1`, while WebMCP requires an origin-keyed agent cluster.
3. The server did not explicitly declare the `tools` Permissions Policy.
4. Browser tests validated tool definitions with a mock but did not compare them with native `document.modelContext.getTools()`.
5. A previous service worker could continue serving stale document and JavaScript responses on localhost.

## v2.3 behavior

- Sends origin-agent-cluster and permissions-policy headers locally and through Vercel, Netlify, Cloudflare Pages, and compatible `_headers` hosts.
- Registers 33 direct imperative tools.
- Calls `getTools()` after registration and reports the discovered count.
- Shows green status only at 33/33.
- Shows an actionable red 0/33 or partial status when native registration is unavailable or fails.
- Exposes `await window.PathwayOSWebMCP.diagnostics()` for exact environment, registration, and discovery details.
- Clears old PathwayOS service workers/caches on localhost once.
